WolfCart · Storefront API

API Documentation

Everything you need to build a merchant storefront using WolfCart product, collection, cart and order data. Build in any framework — Next.js, Astro, plain HTML, Vue, SvelteKit — and upload via the admin panel.

Build anywhere. Your storefront can be built in any technology stack. As long as it calls these API endpoints to fetch data, it will work. Upload the built output as a .zip via the admin panel to go live.

Authentication

All API requests require two headers: an API key for authentication and the tenant slug to identify which merchant's data to return.

Required headers

HeaderValueDescription
Authorization Bearer wc_live_xxxx... API key from admin panel → Merchant → API Keys
x-tenant-slug kpopshop The merchant's unique slug (e.g. kpopshop, myshop)
Content-Type application/json Required for POST and PATCH requests

API key types

PrefixEnvironmentUse
wc_live_LiveReal transactions — use in production storefronts
wc_test_TestTest transactions — use in development only, no real charges
fetch — JavaScript
// All API calls follow this pattern
const response = await fetch(`${API_BASE}/storefront/v1/products`, {
  headers: {
    'Authorization': `Bearer ${API_KEY}`,
    'x-tenant-slug': 'kpopshop',
  }
})
Important: Store your API key in environment variables — never hardcode it in client-side JavaScript. For static storefronts, prefix with NEXT_PUBLIC_ (Next.js) or equivalent for your framework.

Base URL

Base URL
# Production
https://api.wolfcart.shop/storefront/v1
 
# Development (local)
http://localhost:3002/storefront/v1

All endpoint paths below are relative to this base URL.

Response Format

All successful responses follow a consistent envelope format.

Success response
{
  "data": /* the actual payload — array or object */,
  "meta": {
    "total": 124,       // total records (for lists)
    "page": 1,
    "limit": 24,
    "hasMore": true
  }
}
When calling from JavaScript, always read response.data — not the raw response. Use the pattern: const json = await res.json(); const items = json.data ?? json;

Error Handling

StatusCodeMeaning
401unauthorizedMissing or invalid API key
403forbiddenAPI key doesn't have required scope
404not_foundProduct, collection, cart, or order not found
422validation_errorInvalid request body — check the errors array
500server_errorWolfCart server error — retry with backoff
Error response
{
  "error": "not_found",
  "message": "Product 'blue-ring' not found for tenant kpopshop",
  "errors": []  // validation errors array, usually empty
}

Build Anywhere — Upload via Admin

Your storefront does not need to be built with any specific framework. You can use:

  • Next.js (static export) — recommended
  • Astro — excellent for static sites
  • Plain HTML + JavaScript — works perfectly
  • Vue, Nuxt, SvelteKit — any framework with static output
  • Any other static site generator

Build your storefront, then zip the output folder and upload via:

Upload process
# Step 1: Build your storefront (any framework)
npx next build    # Next.js
npm run build     # Astro, Nuxt, SvelteKit etc.
 
# Step 2: Zip the output
zip -r kpopshop-v1.zip ./out/     # or ./dist/ depending on framework
 
# Step 3: Upload via WolfCart admin panel
# Go to: admin.wolfcart.shop/deployments/{tenantId}/upload
# Drop the .zip → preview → Make it live
 
# Result: kpopshop.wolfcart.shop serves your storefront from Cloudflare R2
Requirements for the zip: Must contain index.html at the root. All links and assets should use relative paths or absolute URLs. Images should be hosted externally (Cloudflare R2, Cloudinary, etc.) — not bundled in the zip.

Products

GET /products API key List products with filtering, search & sort

Returns a paginated list of products for the merchant. Supports filtering by collection, searching by name, and sorting.

Query parameters

ParameterTypeRequiredDescription
limitintegeroptionalProducts per page. Default: 24. Max: 100.
pageintegeroptionalPage number starting from 1. Default: 1.
sortstringoptionalnewest | price_asc | price_desc | name_asc | best_selling. Default: newest.
collectionstringoptionalCollection slug to filter by. e.g. womens-necklaces
qstringoptionalSearch query — matches product name and description.
inStockbooleanoptionalSet to true to return only in-stock products.

Cart

The cart is server-side. Create a cart, store the cart ID in localStorage, and pass it with every cart operation. The cart ID persists across sessions.

POST /cart API key Create a new empty cart

Call this when a customer first visits the store (if no cart ID in localStorage). Store the returned id in localStorage as wc_cart_id.

Response
{
  "data": {
    "id": "cart_abc123xyz",
    "items": [],
    "subtotal": 0,
    "itemCount": 0,
    "createdAt": "2025-04-27T10:00:00Z"
  }
}
GET /cart/:cartId API key Get cart with all items
Response
{
  "data": {
    "id": "cart_abc123xyz",
    "items": [
      {
        "id": "item_001",
        "variantId": "var_xyz",
        "productId": "prod_abc123",
        "productName": "Gold Chain Necklace",
        "variantTitle": "Gold / 40cm",

        "lineTotal": 700000,   // price × quantity, cents

POST /cart/:cartId/items API key Add item to cart

Request body

FieldTypeRequiredDescription
variantIdstringrequiredThe variant ID from the product. Use product.variants[0].id for the default variant.
quantityintegeroptionalQuantity to add. Default: 1. Max: variant inventory.
Request body
{ "variantId": "var_xyz", "quantity": 1 }

If the item already exists in the cart, the quantity is incremented. Returns the updated cart object.

PATCH /cart/:cartId/items/:variantId API key Update item quantity
Request body
{ "quantity": 3 }
Set quantity to 0 to remove the item from the cart. Returns the updated cart.
DELETE /cart/:cartId/items/:variantId API key Remove item from cart

Removes the item completely regardless of quantity. Returns the updated cart.

Example request
DELETE /storefront/v1/cart/cart_abc123xyz/items/var_xyz

POST /checkout/initiate API key Initiate payment for an order

Initiates payment after the customer selects a payment method. Call this after POST /orders returns an orderId. The response tells you what to do next — redirect to PayHere, confirm COD, or show bank details.

Request body

FieldTypeRequiredDescription
orderIdstringrequiredOrder ID returned by POST /orders
paymentMethodstringrequired'payhere' | 'directpay' | 'cod' | 'bank_transfer'

Complete code example

JavaScript — Implementation Pattern
// Step 1: Create order
const { data: order } = await wolfcartFetch('/orders', {
  method: 'POST',
  body: { cartId, email, shippingAddress, shippingMethodId }
})

// Step 2: Initiate payment
const { data: pay } = await wolfcartFetch('/checkout/initiate', {
  method: 'POST',
  body: { orderId: order.id, paymentMethod: 'payhere' }
})

// Step 3: Handle response
switch (pay.method) {
  case 'payhere':
  case 'directpay':
    // Both use identical form submission pattern
    const url = pay.payhereUrl || pay.formUrl
    const form = document.createElement('form')
    form.method = 'POST'
    form.action = url
    Object.entries(pay.params).forEach(([k, v]) => {
      const el = document.createElement('input')
      el.type = 'hidden'; el.name = k; el.value = String(v)
      form.appendChild(el)
    })
    document.body.appendChild(form)
    form.submit()
    break
  case 'cod':
    router.push(`/order-success?id=${order.id}&method=cod`)
    break
  case 'bank_transfer':
    router.push(`/order-success?id=${order.id}&method=bank_transfer`)
    break
}

  ogTitle:        string
  ogDescription:  string
  ogImage:        string | null
  canonical:      string

// Helper function to resolve SEO with fallbacks
export function resolveProductSeo(
  product: Product,
  storeUrl: string,
  storeName: string
): SeoMeta {
  return {
    title:         product.metaTitle ?? `${product.name} — ${storeName}`,
    description:   product.metaDescription ?? product.description?.slice(0, 155) ?? '',
    ogTitle:       product.ogTitle ?? product.metaTitle ?? product.name,
    ogDescription: product.ogDescription ?? product.metaDescription ?? '',
    ogImage:       product.ogImageUrl ?? product.images?.[0]?.url ?? null,
    canonical:     product.canonicalUrl ?? `${storeUrl}/products/${product.slug}`,
    noIndex:       product.noIndex ?? false,
    keywords:      product.metaKeywords ?? null,
  }
}

SEO

WolfCart provides per-product SEO fields that you can use in your custom storefront to improve search engine visibility. Each product can have its own meta title, meta description, Open Graph tags, and structured data. If a product has no SEO fields set, fall back to the product name and description.

SEO fields come from two sources:

  1. Product-level: set per product in the merchant dashboard (Growth/Pro plans)
  2. Store-level: fallback values from GET /store → data.seo
SEO fields are available on Growth and Pro plans. Starter plan products return null for all SEO fields — apply your own fallback logic using product name and description.

Fallback priority table

FieldFirst choiceFallback
Title tagproduct.metaTitleproduct.name + store name
Descriptionproduct.metaDescriptionproduct.description.slice(0,155)
OG titleproduct.ogTitleproduct.metaTitle or product.name
OG descriptionproduct.ogDescriptionproduct.metaDescription
OG imageproduct.ogImageUrlproduct.images[0].url
Canonical URLproduct.canonicalUrlconstructed from slug

Product SEO Fields

All SEO fields returned on product objects:

FieldTypeDescription

import type { Metadata } from 'next'

export async function generateMetadata({ params }: { params: { slug: string } }): Promise<Metadata> {
  const { data: product } = await wolfcartFetch(`/products/${params.slug}`)

  const STORE_NAME = process.env.NEXT_PUBLIC_BRAND_NAME ?? 'My Store'

    robots: product.noIndex ? 'noindex, nofollow' : 'index, follow',
    alternates: {
      canonical: product.canonicalUrl ?? `${STORE_URL}/products/${product.slug}`,
    },
    openGraph: {
      type: 'website',
      title: product.ogTitle ?? product.metaTitle ?? product.name,
      description: product.ogDescription ?? product.metaDescription ?? '',
      images: product.ogImageUrl
        ? [{ url: product.ogImageUrl, width: 1200, height: 630 }]
        : product.images?.[0]?.url

      title: product.ogTitle ?? product.name,
      description: product.ogDescription ?? product.metaDescription ?? '',

Next.js Static Export (useEffect approach)

Use this if your storefront is a static export (BUILD_MODE=static):

components/SeoHead.tsx
'use client'
import { useEffect } from 'react'

export function SeoHead({ title, description, ogImage, ogTitle, ogDescription,
                          canonical, noIndex, keywords }) {
  useEffect(() => {
    document.title = title

    function setMeta(name, content, attr = 'name') {
      let el = document.querySelector(`meta[${attr}="${name}"]`)
      if (!el) {
        el = document.createElement('meta')
        el.setAttribute(attr, name)
        document.head.appendChild(el)
      }
      el.setAttribute('content', content)
    }

    function setLink(rel, href) {
      let el = document.querySelector(`link[rel="${rel}"]`)
      if (!el) {
        el = document.createElement('link')
        el.rel = rel
        document.head.appendChild(el)
      }
      el.href = href
    }

    setMeta('description', description)
    setMeta('robots', noIndex ? 'noindex,nofollow' : 'index,follow')
    if (keywords) setMeta('keywords', keywords)

    setMeta('og:title', ogTitle ?? title, 'property')
    setMeta('og:description', ogDescription ?? description, 'property')
    setMeta('og:type', 'product', 'property')
    if (ogImage) setMeta('og:image', ogImage, 'property')

    setMeta('twitter:card', 'summary_large_image')
    setMeta('twitter:title', ogTitle ?? title)
    setMeta('twitter:description', ogDescription ?? description)
    if (ogImage) setMeta('twitter:image', ogImage)

    if (canonical) setLink('canonical', canonical)
  }, [title, description, ogImage, ogTitle, ogDescription, canonical, noIndex])

  return null
}

Plain HTML / Vanilla JS

For non-framework storefronts:

JavaScript
async function applyProductSeo(slug) {
  const { data: product } = await wolfcartFetch(`/products/${slug}`)
  const STORE = 'KPop Shop'
  const BASE = 'https://kpopshop.wolfcart.shop'

  document.title = product.metaTitle ?? `${product.name} — ${STORE}`

  const setMeta = (sel, content) => {
    const el = document.querySelector(sel)
      ?? document.head.appendChild(document.createElement('meta'))
    const attr = sel.includes('property') ? 'property' : 'name'
    const val = sel.match(/["']([^"']+)["']/)?.[1] ?? ''
    el.setAttribute(attr, val)
    el.setAttribute('content', content)
  }

  setMeta('meta[name="description"]',
    product.metaDescription ?? product.description?.slice(0,155) ?? '')
  setMeta('meta[name="robots"]',
    product.noIndex ? 'noindex,nofollow' : 'index,follow')
  setMeta('meta[property="og:title"]',
    product.ogTitle ?? product.metaTitle ?? product.name)
  setMeta('meta[property="og:description"]',
    product.ogDescription ?? product.metaDescription ?? '')
  setMeta('meta[property="og:type"]', 'product')

  const img = product.ogImageUrl ?? product.images?.[0]?.url
  if (img) setMeta('meta[property="og:image"]', img)

  let canonical = document.querySelector('link[rel="canonical"]')
  if (!canonical) {
    canonical = document.createElement('link')
    canonical.rel = 'canonical'
    document.head.appendChild(canonical)
  }
  canonical.href = product.canonicalUrl ?? `${BASE}/products/${product.slug}`
}

Structured Data — JSON-LD

Google uses JSON-LD structured data to show rich results for products — including price, availability, and ratings in search results. Add this to every product page. It is separate from meta tags.

WolfCart products contain all the data needed to generate Product schema.

Generating Product JSON-LD — JavaScript
function buildProductSchema(product, storeUrl, storeName) {
  const prices = product.variants?.map(v => v.price) ?? [product.price]
  const inStock = product.variants?.some(v => v.inventory > 0)
    ?? product.inStock

  return {
    '@context': 'https://schema.org',
    '@type': 'Product',
    name: product.name,
    description: product.metaDescription ?? product.description,
    image: product.images?.map(img => img.url) ?? [],
    url: `${storeUrl}/products/${product.slug}`,
    sku: product.variants?.[0]?.sku ?? undefined,
    brand: {
      '@type': 'Brand',
      name: storeName,
    },
    offers: {
      '@type': 'AggregateOffer',
      priceCurrency: 'LKR',
      lowPrice: (Math.min(...prices) / 100).toFixed(2),
      highPrice: (Math.max(...prices) / 100).toFixed(2),
      offerCount: product.variants?.length ?? 1,
      availability: inStock
        ? 'https://schema.org/InStock'
        : 'https://schema.org/OutOfStock',
      offers: (product.variants ?? []).map(v => ({
        '@type': 'Offer',
        price: (v.price / 100).toFixed(2),
        priceCurrency: 'LKR',
        availability: v.inventory > 0
          ? 'https://schema.org/InStock'
          : 'https://schema.org/OutOfStock',
        sku: v.sku ?? undefined,
        seller: { '@type': 'Organization', name: storeName },
      })),
    },
  }
}

// Inject into page:
function injectJsonLd(schema) {
  const existing = document.getElementById('product-schema')
  const el = existing ?? document.createElement('script')
  el.id = 'product-schema'
  el.type = 'application/ld+json'
  el.textContent = JSON.stringify(schema)
  if (!existing) document.head.appendChild(el)
}

// Usage:
const schema = buildProductSchema(product, STORE_URL, STORE_NAME)
injectJsonLd(schema)

Sitemap

A sitemap.xml helps Google discover and index all your product pages. Generate one at build time using the WolfCart API to fetch all active products and collections.

scripts/generate-sitemap.mjs
// Run after: pnpm build:storefront {slug}

const API_BASE = process.env.NEXT_PUBLIC_API_BASE_URL
const API_KEY  = process.env.NEXT_PUBLIC_STOREFRONT_API_KEY
const SLUG     = process.env.NEXT_PUBLIC_TENANT_SLUG
const BASE_URL = `https://${SLUG}.wolfcart.shop`

async function fetchAll(path) {
  const res = await fetch(`${API_BASE}/storefront/v1${path}`, {
    headers: { 'Authorization': `Bearer ${API_KEY}`, 'x-tenant-slug': SLUG },
  })
  const { data } = await res.json()
  return data
}

const [products, collections] = await Promise.all([
  fetchAll('/products?limit=100&sort=newest'),
  fetchAll('/collections'),
])

const urls = [
  { loc: BASE_URL, priority: '1.0', changefreq: 'daily' },
  { loc: `${BASE_URL}/products`, priority: '0.9', changefreq: 'daily' },
  { loc: `${BASE_URL}/collections`, priority: '0.8', changefreq: 'weekly' },
  ...products.map(p => ({
    loc: `${BASE_URL}/products/${p.slug}`,
    priority: '0.8',
    changefreq: 'weekly',
  })),
  ...collections.map(c => ({
    loc: `${BASE_URL}/collections/${c.slug}`,
    priority: '0.7',
    changefreq: 'weekly',
  })),
]

const xml = `<?xml version="1.0" encoding="UTF-8"?>
<urlset xmlns="http://www.sitemaps.org/schemas/sitemap/0.9">
${urls.map(u => `  <url>
    <loc>${u.loc}</loc>
    <changefreq>${u.changefreq}</changefreq>
    <priority>${u.priority}</priority>
  </url>`).join('\n')}
</urlset>`

import { writeFileSync } from 'fs'
writeFileSync('out/sitemap.xml', xml)
console.log(`Sitemap: ${urls.length} URLs written to out/sitemap.xml`)
After deploying, submit your sitemap to Google Search Console:
1. Go to search.google.com/search-console
2. Add your store domain
3. Sitemaps → Add sitemap → enter 'sitemap.xml'
Google will crawl your products within 1-7 days.

SEO Checklist

Use this checklist when building a custom storefront to make sure all SEO requirements are met before going live.

GROUP 1 — Meta Tags (every page)

  • [ ] <title> tag set on every page (product name + store name)
  • [ ] <meta name="description"> set (140-160 characters)
  • [ ] <meta name="robots"> set (index,follow for live products)
  • [ ] <link rel="canonical"> points to correct URL
  • [ ] No duplicate title tags across pages

GROUP 2 — Open Graph (social sharing)

  • [ ] og:title set on every product page
  • [ ] og:description set
  • [ ] og:image set — minimum 600×315px, ideally 1200×630px
  • [ ] og:type = "product" on product pages
  • [ ] og:url matches canonical URL
  • [ ] twitter:card set to summary_large_image

GROUP 3 — Structured Data

  • [ ] Product JSON-LD on every product page
  • [ ] Product schema includes: name, description, image, offers
  • [ ] Offers include: price, priceCurrency, availability
  • [ ] WebSite JSON-LD on homepage
  • [ ] Validated with Google Rich Results Test

GROUP 4 — Technical

  • [ ] sitemap.xml generated and submitted to Google Search Console
  • [ ] All product images served from CDN (Cloudflare R2)
  • [ ] Page load time < 3 seconds (use Lighthouse)
  • [ ] Mobile-friendly (use Google Mobile-Friendly Test)
  • [ ] HTTPS enabled (Cloudflare handles this automatically)
  • [ ] No broken links on product pages
